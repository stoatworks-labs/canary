# dbCANary rev A — fabrication outputs

**100 × 81 mm, 4 layer, 1.6 mm, 76 placements (top side only).**
38 BOM lines in `generic/`, 40 in `jlcpcb/` — all grouped by
orderable part. DRC: **0 errors, 0 unconnected items**, 31 accepted silkscreen
warnings.

A complete, self-contained upload set — **gerbers + BOM + pick-and-place** — in
JLCPCB's expected format, plus a vendor-neutral `generic/` set to convert from for
any other fab or for building one by hand. (The private working tree also held
PCBWay and PCB Train sets; they are not included in the public repo.)

## The BOMs are not copies of each other

Each vendor gets a different BOM **on purpose**, and diffing them is not a way
to find errors:

- **JLCPCB** is costed in LCSC part numbers, and omits the through-hole
  connectors it will not hand-fit.
- **PCBWay** carries MPN + manufacturer for turnkey sourcing.
- **PCB Train** is re-sourced against **UK** stock. Roughly half the passives
  are substituted, because the design's originals are China-domestic parts no
  Western distributor carries. Those substitutions and their rationale are in
  the `Notes` column (that set is not included in the public repo).
- **`generic/`** is the union: every part on the board, on one line per orderable
  part, carrying whichever sourcing is known plus the UK alternate as a note.

## Regenerating

The `generic/` set, and any vendor gerber archive or CPL derived from it, comes
from the board via:

```bash
python3 hardware/scripts/fab_package.py hardware/dbcanary.kicad_pcb
```

That is safe to re-run: it rebuilds `generic/` from scratch and **never**
overwrites a vendor BOM or a vendor-plugin-generated file that already exists.
The JLCPCB and PCBWay packages come from those vendors' own KiCad plugins, and
the PCB Train BOM from `hardware/scripts/make_pcbtrain_bom.py`.

### Always run this after a vendor plugin

Both plugins group BOM lines by the schematic **Value** string rather than by
part number, and they emit the through-hole parts with no part number at all.
Ours carry net annotations — `100nF (BST)`, `100nF (VBG)` and plain `100nF` are
all the same CL05B104KO5NNNC — so one 14-piece line leaves as three lines of 1,
12 and 1, and the quoting desk prices each separately.

That cost real money on the rev A PCBWay quote: the two-piece
CL21A226MAQNNNE line was quoted as two 1-piece lines at USD 1.727 each — USD
17.27 for ten 22 µF capacitors LCSC sells at USD 0.33 — and PCBWay came back
asking for J301 and SW201 by hand because both arrived blank.

```bash
# PCBWay: consolidate, refill the through-hole part numbers, and mark
# whichever parts this order is not paying them to place
python3 hardware/scripts/consolidate_vendor_bom.py \
    hardware/fab/pcbway/dbcanary-pcbway-bom.csv --dnp J201,J202,J401

# JLCPCB: consolidate only. Its Economic tier is top-side SMD, so all five
# through-hole parts stay unsourced and get marked Do Not Place at review.
python3 hardware/scripts/consolidate_vendor_bom.py \
    hardware/fab/jlcpcb/dbcanary-jlcpcb-bom.csv --no-fill
```

It refuses to write if the designator count changes, so it cannot quietly lose
a part. Part numbers come from [`hand-fit-parts.json`](hand-fit-parts.json), not
from a dict inside a script — `jlc_verify.py`'s `THT_MPN` filled the etherCON
manufacturer in once and the 2026-08-04 plugin run wiped it straight back out.

**This does not touch the schematic.** The Value annotations are the only record
of which pin each part serves — `(BST)` is the AP63200 bootstrap,
`(VBG)`/`(TOCAP)`/`(TCT)`/`(RCT)` are W5500 pin names, `LAN`/`CAN`/`ERR`/`ON`
are the LED functions. Deleting them to satisfy a CSV grouping quirk would trade
real documentation for a cosmetic fix.

`generic/gerbers/` (the loose expansion of `generic/dbcanary-gerbers.zip`) is
not tracked in git; the archive is.
